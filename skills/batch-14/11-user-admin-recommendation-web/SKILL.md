# Recommendation web experience

The member sees cards with an approved display name, age display, city-level
location, approved primary photo, a short introduction, shared strengths, the
conditions they set that matched, topics to explore and information gaps — never
a percentage, the other member's score, their full criteria, contact details or
exact birth date. The empty state explains, in aggregates, which conditions
reduced the pool and what can be changed. Settings cover pacing, quantity,
allowed relaxations, exploration and behavioural personalisation, never a way to
bypass someone else's conditions. The transparency page names the data categories
used and the ones never used. Operators get a supervision centre: strategies,
features, constraints, batches, aggregate diagnostics, exposure, cold start,
feedback, evaluations, experiments, incidents and audit — with no control that
could force a pairing, edit a score or bypass a constraint.
