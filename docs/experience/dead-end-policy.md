# Dead-end and experience-closure policy

A critical route is release-blocking when it is unreachable, has a broken target, lacks help, forms a redirect loop or has no return/recovery path. Static checks run from versioned manifests; runtime scans persist governed findings in `experience_dead_end_findings`.

Critical capabilities require discoverable entry, real action, visible status, next step, return path, recovery, help, authorization declaration and zero critical dead ends. Technical closure never overrides domain, security, data or quality failures.

Production certification requires independent, checksum-bound user E2E, administrator E2E, security, dead-end, Batch 21 quality and Batch 22 UI evidence. Until every named gate is accepted, status remains `NOT_CERTIFIED` and release is fail-closed.
