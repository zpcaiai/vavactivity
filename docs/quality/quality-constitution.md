# VAV 质量宪章

VAV 的“完成”由可追踪的业务闭环和当前证据定义，而不是由页面、接口或代码文件的存在定义。任何缺失、过期、无法校验或与当前 Git 提交不一致的证据都按失败处理。

## 强制原则

1. 每个关键需求必须可追踪到能力、业务流、入口、API、服务、状态、数据库、事件、权限、指标、测试和证据。
2. 每条关键业务流必须有成功、失败、取消或过期终态，并提供管理员恢复或补偿路径。
3. Blocker 失败、非豁免项失败以及 Critical 缺口均产生 `NO_GO`；总分不能覆盖关键失败。
4. Required 失败只可由限定范围、独立审批、含缓解措施且未过期的 Waiver 暂时处理。生产环境不接受 `CONDITIONAL_GO`。
5. 证据必须绑定 release、Git commit、environment、校验和和有效期；截图不能单独证明后端状态正确。
6. 需求、门禁、Waiver、证据和发布认证均保留不可抵赖的管理员审计，并对审批执行职责分离。
7. 用户屏蔽绕过、跨用户数据泄漏、支付权益不一致、隐私删除遗漏、关键数据不可恢复和 Critical 安全问题不可豁免。

## 责任边界

业务模块负责实现和生成证据；质量控制平面负责注册、关联、验证、检测缺口和执行发布门禁。外部渗透测试、真实恢复演练、UAT 和生产审批必须由真实主体提供，系统不得伪造通过。
