# Page Layout Patterns

Every application shell exposes one skip link and one primary main target. After route changes, focus moves to the first page heading. User pages choose reading, standard or wide width. Forms show summary errors, field errors, pending validation, draft recovery and a mobile-safe action bar.

Administrator pages inherit the shell heading, exact route permission and compact density. Tables provide captions, header associations, selected-row names, empty states and a responsive card representation. Review pages separate evidence, before/after content and approve/reject actions.

The page audit maps router components to page- or shell-owned heading contracts and rejects undocumented gaps.
